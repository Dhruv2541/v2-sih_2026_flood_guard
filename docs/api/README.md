# API Documentation & Contracts

## Base URL & Versioning
All primary API endpoints are prefixed with the configured `API_PREFIX` (default: `/api/v1`).

Interactive API documentation is automatically generated by FastAPI:
- **Swagger UI**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- **ReDoc**: [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)

## Foundation Endpoints (Phase 1)

### 1. Application Liveness Check
Checks whether the FastAPI application process is running and able to handle incoming requests. This endpoint has **no dependencies** on PostgreSQL, Supabase, ML models, or external APIs.

- **Method**: `GET`
- **Path**: `/api/v1/health`
- **Success Status**: `200 OK`
- **Response**:
  ```json
  {
    "status": "ok"
  }
  ```

### 2. Database Connectivity Check
Explicitly validates connectivity to the configured Supabase PostgreSQL database using an active test query (`SELECT 1`).

- **Method**: `GET`
- **Path**: `/api/v1/health/db`
- **Success Status**: `200 OK`
- **Success Response**:
  ```json
  {
    "status": "ok",
    "database": "connected"
  }
  ```
- **Failure Status**: `503 Service Unavailable`
- **Failure Response**:
  ```json
  {
    "status": "error",
    "database": "disconnected",
    "message": "Database is unavailable or connection string not configured."
  }
  ```
  *(Note: Sensitive information such as passwords, hostnames, and internal stack traces are never exposed in failure responses).*

## Planned Endpoints (Future Phases)
The following contracts will be implemented once data models and ML interfaces are finalized:
- `GET /api/v1/regions` - List monitored regions/grids in Assam
- `GET /api/v1/predictions/live` - Current ~6-hour flood risk predictions by region
- `GET /api/v1/observations/latest` - Latest environmental metrics (rainfall, water levels)
- `POST /api/v1/alerts/subscribe` - Notification preferences (community/admin alerts)
